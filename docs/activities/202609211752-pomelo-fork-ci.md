# Atividade — fork Pomelo no CI do Sufficit.Client

## Objetivo

Recuperar o workflow `Publish Packages` depois que o target `net10.0` passou a
resolver transitivamente `Pomelo.EntityFrameworkCore.MySql 10.0.0`, versão que a
Sufficit mantém em fork e que ainda não está publicada no NuGet.org.

## Estado inicial

- o run `35648602707`, job `106495080563`, falhava no `dotnet restore` com
  `NU1102`;
- o job executava em `ubuntu-latest`, com a label e o runner do GitHub Actions;
- o log mostrava somente NuGet.org e encontrava, no máximo, Pomelo 9.0.0;
- o pacote correto já existia no feed privado do CI em
  `/opt/sufficit-nuget-feed/Pomelo.EntityFrameworkCore.MySql.10.0.0.nupkg`;
- não havia runner dedicado cadastrado para `sufficit-client`.

## Alterações

### Infraestrutura do CI

- criada a instância dedicada `/home/runner/r-client` a partir do template limpo
  do runner `2.337.0`;
- registrado o runner `linux-ci-client` somente no repositório
  `sufficit/sufficit-client`;
- instalado e iniciado o serviço
  `actions.runner.sufficit-sufficit-client.linux-ci-client.service`;
- verificado o runner online e ocioso com as labels
  `[self-hosted, Linux, X64, aireset-ci]`.

### Workflow

- `.github/workflows/publish.yml` passou de `ubuntu-latest` para
  `[self-hosted, Linux, X64, aireset-ci]`;
- o SDK declarado foi atualizado de `9.0.x` para `10.0.x`, acompanhando os TFMs
  atuais `netstandard2.0;net7.0;net10.0`;
- restore, build, pack e push permaneceram inalterados; somente o ambiente que
  já contém o fork foi selecionado.

## Decisões

- o `.nupkg` do fork não foi duplicado neste repositório nem enviado ao
  NuGet.org;
- foi usado o feed central já mantido no runner privado, alinhado aos workflows
  de `sufficit-base`, `sufficit-efdata` e `sufficit-standard`;
- nenhuma versão de dependência foi reduzida: `10.0.0` continua sendo o provider
  correto para EF Core 10;
- foi criada uma instância de runner própria, sem reaproveitar ou interromper
  runners de outros repositórios.
